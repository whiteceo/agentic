# AI 에이전틱 시스템 구축 규약

> **원본 이동(2026-11-15)**: 이 저장소는 이제 연합형 에이전틱 운영 모델(FAOM)의 **릴리즈 판을 내보내는 공개 창구**다. 작업 원본은 비공개 통합 저장소(DDD 방법론과 FAOM을 함께 설계하는 곳)로 옮겼다. 지금 보이는 문서는 옮기기 직전(b526ca7) 판을 그대로 둔 것이고, 다음 판부터는 릴리즈할 때만 여기에 올린다.

> 체계 이름: **연합형 에이전틱 운영 모델(Federated Agentic Operating Model, FAOM)**. 전체 그림은 `architecture/개념_아키텍처.md`.

AI를 쓰는 업무 환경(PO/PM · UIX 디자이너 · FE/BE 개발자 · 코딩 에이전트)에서 정본과 코드를 하나의 흐름으로 맞추는 규약 문서 모음.

| 파일 | 누가 · 언제 |
| :--- | :--- |
| `AI_에이전틱_핵심규약.md` | 모든 AI가 매일. 저장소에 `AGENTS.md`로 설치 |
| `AI_에이전틱_프로젝트_설치서.md` | 세팅 담당이 프로젝트를 추가할 때 한 번 (설정 질문 12개 포함) |
| `AI_에이전틱_합류_안내.md` | 새로 합류한 사람이 처음 한 번 |
| `skills/` | 스킬 5종 원문(`SKILL.md`), 설치 때 각 저장소 `.claude/skills/`로 복사 |
| `AI_에이전틱_선택_부록.md` | 디자인 시스템 · 계약 테스트 · 계산기 · 메신저 알림 (켠 팀만) |
| `AI_에이전틱_환경_가이드.html` | 사람 브리핑용 시각 가이드 |
| `AI_에이전틱_검토로그.md` | 검토 지적과 결정 기록 |

가이드는 GitHub Pages에서 열면 MD 다운로드 링크가 함께 동작한다.

## 설계 · 연구 문서 (배포 전 작업본)

| 폴더 · 파일 | 무엇 |
| :--- | :--- |
| `architecture/개념_아키텍처.md` | 가장 바깥 그림(C4 1단계): 실행 평면(에이전틱 도메인) · 관제 평면 · DDD 대응 · 용어 정의 · 흐름 |
| `architecture/관제_평면_설계.md` | 관제 평면 부품별 책임 · 주고받는 것 · 저장 · 멈추면(C4 2단계) |
| `architecture/관리_계층_설계.md` | 관리 계층(테넌트 → 조직 → 팀 → 에이전틱 도메인): 칸 · 역할 · 정책 상속 · 정지 범위 · 관측 요약 |
| `architecture/에이전틱_도메인_설계.md` | 에이전틱 도메인 하나의 안쪽(C4 3단계): 에이전트 다섯 · 검사 넷 · 넓히기 |
| `architecture/판정_기준_작성법.md` | 판정 기준 항목의 꼴(읽는 폭 · 기계 몫 · 판단 몫 · 필요한 입력), 갈림이 나왔을 때 기준 고치기 |
| `architecture/실행_연결.md` | 워크플로 · 계정 · 관문 수준(C4 4단계 초안, 시범 뒤 설치서로) |
| `tools/policy_check.py` | 정책 합침 검사의 기준 구현(실행 연결 10절 2 ~ 4번), 시험 `tools/test_policy_check.py` |
| `tools/run_record_check.py` | 판정 리포트 기록 줄 검사의 기준 구현(10절 6 · 7번), 시험 `tools/test_run_record_check.py` |
| `policies/` | 테넌트 · 도메인 정책 예시(실행 연결 9-1). 이 저장소의 `check` 워크플로가 시험과 함께 이 예시로 정책 검사를 돌린다 |
| `research/에이전틱_방법론_조사.md` | 방법론 조사 기록(차수별로 한 파일에 누적) |
| `discussions/DDD_안건.md` | DDD 방법론 쪽과 논의할 안건 |

문서 관리 규칙: 주제마다 파일 하나. 문서마다 머리에 판 · 층 · 상태 · 위아래 문서 표를 두고, 본문은 목적과 범위 → 본문 → 남은 결정 순서로 쓴다. 판(초안 n)은 파일 안 제목과 git 이력으로만 남기고, 판마다 파일이나 브랜치를 새로 만들지 않는다. 개정 기록은 `AI_에이전틱_검토로그.md`에만 둔다.
